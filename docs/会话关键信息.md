# 会话关键信息

本次救砖的完整排障过程与关键结论，供复现和参考。

## 一、诊断阶段

### 初始症状

- 设备管理器识别到 "Kindle Internal Storage"（USB ID `1949:0004`）
- 磁盘显示：`Size=0`、`PartitionStyle=RAW`、`OperationalStatus=No Media`、无容量、D 盘 0 字节
- **结论**：eMMC 分区表/系统被写坏，但 U-Boot 大概率完好

### 关键转折

- 设备切换为 `18D1:4E40`，识别名 "Kindle"，序列号 `02722XXXXXXXL3`，状态为缺驱动
- 确认 `18D1:4E40` 是 Google/Android fastboot 模式
- 设备序列号 `905A22XXXXXXX25`（USB 存储模式）确认机型为 **KPW2**（90 开头）

## 二、准备阶段

### 驱动安装

1. 下载 Google 官方 USB 驱动 `usb_driver_r13-windows.zip`
2. 解压后使用 `android_winusb.inf`（内含 `18D1:4E40` 条目）
3. 以管理员权限安装（`pnputil /add-driver ... /install`，需要 UAC 确认）
4. 安装后设备显示为 "Android Bootloader Interface"，`fastboot devices` 可识别

### 刷机包获取

- 原下载页 `kdroid.club/firmtest/kindle/` 已 404
- 通过 web.archive.org CDX 查询发现存档：
  - `http://kdroid.club/firmtest/kindle/kindle.191115/kpw2.191115.zip`（200，465MB）
- 用 `https://web.archive.org/web/20220905122338id_/...`（`id_` 后缀取原始文件）完整下载
- ZIP 完整性测试通过，内含 `fastdownload.exe` + 系统镜像

## 三、刷机阶段

### fastboot 超时问题

- 现象：`fastboot devices` 能看到设备（`???????????? fastboot`），但 `getvar` 全部超时
- 原因：fastboot 会话约 5 秒无命令自动退出（ZephRay 文章提到）
- 解决：让设备重新进入 fastboot 模式（按住电源键 15 秒）后立即操作

### 成功刷机

- 运行 `fastdownload.exe`，检测到设备后显示菜单
- 选择 **选项 4「转换为原始系统(Kindle)」**
- 输出关键信息：
  - `###Ver:Z05`
  - `###原生系统！Downloading!`
  - `Downloading system:` → 100%
  - `Downloading kernel:` → 100%
  - `###完成！Rebooting!`
  - `###All Done.`

## 四、验证阶段

刷机后设备自动重启，电脑端验证结果：

- 磁盘：MBR 分区表、3.37GB、`Online` / `Healthy`
- 卷：FAT32、卷标 "Kindle"
- 目录：`documents`（含官方用户指南）、`fonts`、`system`
- 系统版本：`D:\system\version.txt` = `Kindle 5.12.2 (356962 025)`
- 型号确认：`D:\breakfast` = `wario`（KPW2 开发代号）
- 系统运行：电脑同时识别为 Kindle 存储盘 + Kindle 便携设备（WPD/MTP，仅系统启动后出现）
- 可写性：写入/删除测试文件通过

## 五、经验教训

1. **半砖判断**：USB 能识别但磁盘 0 字节 → 引导层完好，系统层损坏，可救
2. **fastboot 超时**：连接要快，设备 5 秒无命令即退出
3. **官方工具优先**：CrackDroid 官方 `fastdownload.exe` 选项 4 可一键转回原生系统（含重建分区表）
4. **网页存档是好资源**：官网下线后，web.archive.org 的 `id_` 模式可下载原始大文件
5. **型号确认**：设备内 `breakfast` 文件内容为开发代号（`wario` = KPW2）
